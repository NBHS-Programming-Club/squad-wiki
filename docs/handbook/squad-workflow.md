# Workflow and Collaboration

This handbook section defines a practical workflow for project-based learning. These are **recommended conventions** that teams can adapt.

## Squad project workflow

1. **Propose an idea** with target users and expected value.
2. **Agree on a realistic MVP** that can be delivered in available time.
3. **Create milestones and success criteria** to track progress.
4. **Learn and prototype** the required technologies.
5. **Build iteratively using Git** with small pull requests.
6. **Test and request feedback** from teammates and mentors.
7. **Document and present** the final project.

## Teamwork guidance

- Assign clear ownership for features while sharing knowledge.
- Hold short check-ins on blockers and next steps.
- Rotate presentation and documentation responsibilities.

## Code review guidance

- Keep pull requests small and focused.
- Review for correctness, clarity, and maintainability.
- Give actionable feedback with examples.
- Re-test changed behavior before merging.

## Version control guidance

- Use feature branches for all changes.
- Write descriptive commit messages.
- Rebase or merge `main` regularly to reduce conflicts.
- Tag milestones or release points for demos.

## Technical presentation guidance

- Explain the problem, MVP, and architecture.
- Show a working demo and test evidence.
- Discuss tradeoffs, limitations, and next steps.

## Handover guidance

- Store setup instructions and architecture notes in the repository.
- Document known issues and future improvements.
- Leave enough context for future squad members to continue the project.
