6. Troubleshooting

Most errors are useful reports from a tool. Slow down, make the failure repeatable, and change one variable at a time.

"Command not found" or the editor cannot find a tool

Confirm the tool is installed, restart the terminal, and check its version. On Windows, verify the installer added the tool to PATH. On macOS or Linux, check the shell configuration. Record the exact command and operating system before asking for help.

The program runs but gives the wrong answer

Write the smallest input that demonstrates the wrong result. Print or inspect intermediate values. Compare the program with a hand-worked example, then add that example as a test so the bug does not return.

Git says there are conflicts or rejected changes

Do not delete files to make the message disappear. Read git status, inspect the conflicting sections, keep the intended content, then test before committing. Ask a mentor if you are unsure which version is correct.

I copied a tutorial and do not understand my own project

Stop adding features. Rename variables, explain each function in your notes, and rebuild one small part without looking. The goal is transferable understanding, not a particular code listing.

I am stuck and do not know what to ask

Use this format: "I am trying to ___. I expected ___. Instead I got ___. I tested ___. Here is the smallest relevant code/error: ___." This gives another person enough context to help without guessing.
